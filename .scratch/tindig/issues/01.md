# 01 — Create an offline catalog and typed price lookup

Status: closed | Published: https://github.com/Shirooo098/Aira/issues/1

Suggested lead: D4. Developer numbers are roles, not assigned GitHub accounts. Each lead owns a complete UI/action/persistence/verification slice and coordinates shared schema changes with D3.

## What to build

Install Aira (Artificial Intelligence for Retail Assistance), enter a product, restart the app, and retrieve its saved price by typing.

## Acceptance criteria

- [x] React Native/TypeScript Android build installs on the Oppo; local SQLite persists product identity, variant, selling unit, and integer-centavo price.
- [x] Ask price, Sell, and Manage products are visible modes with short audio cues; changing modes performs no business write.
- [x] Typed lookup shows saved prices, unknown-product feedback, or accessible choices for ambiguity; no invented values.
- [x] Record framework/native dependency decisions and obtain required approval before adding material dependencies. Document quantity-unit conventions before later stock work.
- [x] Verify offline persistence and application-level lookup behavior; model-independent foundation must not wait for speech.

## Blocked by

None — can start immediately.

## Verification and constraints

Testing workflow (confirmed 2026-10-10): use Expo Go for initial phone testing of catalog entry, lookup, persistence and modes; follow README.md. Use a standalone release APK for final airplane-mode acceptance. Later custom native modules may require an Expo development build.

Proposed test seams: application actions against real temporary SQLite for business behavior, and actual-device acceptance for speech/OCR/inference. No mocked model benchmark claims. No silent fallback, secret exposure, autonomous payment verification, or unconfirmed financial writes. Preserve unrelated changes. No commit/push unless separately requested.
