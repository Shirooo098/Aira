# 04 — Set stock counts and record deliveries

Status: ready-for-agent | Published: https://github.com/Shirooo098/Aira/issues/4

Suggested lead: D3. Developer numbers are roles, not assigned GitHub accounts. Each lead owns a complete UI/action/persistence/verification slice and coordinates shared schema changes with D3.

## What to build

Maintain the quantity on hand through clearly distinct count corrections and deliveries.

## Acceptance criteria

- [ ] Set stock replaces the count; add delivery increments it; each shows before/after values and requires confirmation.
- [ ] Missing quantity is not silently zero; selling unit and quantity precision follow a documented decision.
- [ ] Price-only edits leave stock unchanged; invalid quantities and save failures are visible.
- [ ] Persist quantity change history and verify counts/deliveries with a real temporary SQLite database.

## Blocked by

- #1 — Create an offline catalog and typed price lookup

## Verification and constraints

Proposed test seams: application actions against real temporary SQLite for business behavior, and actual-device acceptance for speech/OCR/inference. No mocked model benchmark claims. No silent fallback, secret exposure, autonomous payment verification, or unconfirmed financial writes. Preserve unrelated changes. No commit/push unless separately requested.
