# 06 — Dictate and review catalog changes

Status: ready-for-agent | Published: https://github.com/Shirooo098/Aira/issues/6

Suggested lead: D2. Developer numbers are roles, not assigned GitHub accounts. Each lead owns a complete UI/action/persistence/verification slice and coordinates shared schema changes with D3.

## What to build

Speak a product name, selling price and quantity, review the extracted fields, and save intentionally.

## Acceptance criteria

- [ ] Support the owner example 'Lucky Me chicken, 15 pesos, 10 pieces'; allow text correction and visible field review.
- [ ] Separate new product, price update, set-count and add-delivery intents; missing variant/unit/quantity requires clarification.
- [ ] Allow spoken catalog confirmation only within an active reviewed draft; changing mode cannot save it.
- [ ] Verify duplicate product handling, unconfirmed drafts, cancellation, price-only stock preservation and invalid values.

## Blocked by

- #2 — Transcribe Filipino speech with a bundled model
- #4 — Set stock counts and record deliveries

## Verification and constraints

Proposed test seams: application actions against real temporary SQLite for business behavior, and actual-device acceptance for speech/OCR/inference. No mocked model benchmark claims. No silent fallback, secret exposure, autonomous payment verification, or unconfirmed financial writes. Preserve unrelated changes. No commit/push unless separately requested.
