# 07 — Complete a cash sale with consistent inventory

Status: ready-for-agent | Published: https://github.com/Shirooo098/Tindig/issues/7

Suggested lead: D3. Developer numbers are roles, not assigned GitHub accounts. Each lead owns a complete UI/action/persistence/verification slice and coordinates shared schema changes with D3.

## What to build

Create a typed/tapped purchase draft, confirm cash received, and save a sale with correct stock.

## Acceptance criteria

- [ ] Display items, snapshot unit prices, quantities, total, tender and change; require an explicit final confirmation button.
- [ ] Insufficient recorded stock requires a deliberate count correction, never silent negative inventory.
- [ ] Commit sale, payment and stock changes atomically; repeated confirmation does not duplicate the operation.
- [ ] Verify failure rollback, duplicate confirmation, exact centavo arithmetic, persistence and later price edits not rewriting old sales.

## Blocked by

- #4 — Set stock counts and record deliveries

## Verification and constraints

Proposed test seams: application actions against real temporary SQLite for business behavior, and actual-device acceptance for speech/OCR/inference. No mocked model benchmark claims. No silent fallback, secret exposure, autonomous payment verification, or unconfirmed financial writes. Preserve unrelated changes. No commit/push unless separately requested.
