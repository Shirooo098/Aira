# 08 — Speak and correct an order before checkout

Status: ready-for-agent | Published: https://github.com/Shirooo098/Tindig/issues/8

Suggested lead: D2. Developer numbers are roles, not assigned GitHub accounts. Each lead owns a complete UI/action/persistence/verification slice and coordinates shared schema changes with D3.

## What to build

Prepare a sale by voice and correct quantities in its visible draft before confirmation.

## Acceptance criteria

- [ ] Resolve spoken items via the shared catalog/alias behavior; clarify products/variants rather than guessing.
- [ ] Support bounded contextual corrections such as 'isa lang pala'; ambiguous correction targets require selection.
- [ ] Mode changes and audio cannot finalize the sale; define draft interruption/resume behavior explicitly.
- [ ] Verify multi-item orders, correction, unknown items and final cash sale through the existing transaction boundary.

## Blocked by

- #5 — Ask prices by voice using confirmed aliases
- #7 — Complete a cash sale with consistent inventory

## Verification and constraints

Proposed test seams: application actions against real temporary SQLite for business behavior, and actual-device acceptance for speech/OCR/inference. No mocked model benchmark claims. No silent fallback, secret exposure, autonomous payment verification, or unconfirmed financial writes. Preserve unrelated changes. No commit/push unless separately requested.
