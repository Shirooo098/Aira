Suggested lead: D3. Developer numbers are roles, not assigned GitHub accounts. Each lead owns a complete UI/action/persistence/verification slice and coordinates shared schema changes with D3.

## What to build

Review and reverse incorrect records while preserving an understandable correction history.

## Acceptance criteria

- [ ] Permit unpaid-sale cancellation; require explicit review/reversal of affected repayments before cancelling paid-down credit sales.
- [ ] Define paid cash/GCash sale and cross-debt repayment reversal transitions; record handling never triggers a real refund.
- [ ] Restore stock exactly once on cancellation; reverse relevant debt/payment effects atomically and retain history.
- [ ] Choose and document later-reversal report attribution with worked examples for subsequent dashboard queries.
- [ ] Test duplicate cancellation, already-reversed payment, cross-debt allocation, failure rollback and no invented refund.
